Configurar o relay do PairLAN no Cloudflare

Passo a passo para ligar o modo internet do PairLAN: o relay (Worker + Durable Objects) e o TURN do Cloudflare Realtime. Tudo cabe no plano grátis. Leva uns 15 minutos.

1O que você vai montar

PC A ──wss──▶ Worker pairlan-relay ──▶ sala da dupla (Durable Object) ◀──wss── PC B │ ├─ /users nome de usuário → chave pública └─ credencial TURN temporária (o segredo fica só no Worker) Tela, voz e áudio (WebRTC): direto entre os PCs via STUN. Se o NAT bloquear, passa pelo TURN do Cloudflare.
  • Chat, anexos e sinalização passam pelo relay, cifrados ponta a ponta (Ed25519 + X25519 + AES-256-GCM). O relay só repassa bytes e não lê nada.
  • Mídia vai por WebRTC, que já é cifrado (DTLS-SRTP), mesmo quando passa pelo TURN.
  • A sala só abre quando os dois se adicionaram. Ninguém entra chutando nome.

2Antes de começar

  • Node.js 20 ou mais novo (nodejs.org/en/download). Confira com node -v.
  • O repositório do PairLAN clonado na sua máquina.
  • Um navegador para logar no Cloudflare.
git clone https://github.com/uesleinasch/pairlan.git
cd pairlan/relay
npm install

3Criar a conta Cloudflare

  1. Abra dash.cloudflare.com/sign-up e crie a conta (e-mail e senha). Confirme o e-mail.
  2. Não precisa de domínio próprio. O relay usa o subdomínio grátis *.workers.dev.
  3. No primeiro deploy, o wrangler pede para você escolher esse subdomínio (ex.: ana-dev). Dá para ver ou trocar depois em workers.dev routing.

4Instalar e logar o wrangler

O wrangler já vem como dependência em relay/ (passo 2). Faça o login, que abre o navegador para autorizar:

npx wrangler login
npx wrangler whoami

O whoami deve mostrar o seu e-mail e o Account ID. Referência: instalar o wrangler e comandos do wrangler.

5Publicar o relay

Ainda dentro de relay/:

npm run deploy

O deploy cria o Worker pairlan-relay, as duas classes de Durable Object (UserDO e RoomDO, com SQLite, o único tipo do plano Free) e os limites de taxa. No fim aparece a URL:

https://pairlan-relay.<seu-subdominio>.workers.dev

Guarde essa URL. É o endereço do servidor que vai no app.

6Criar a chave TURN

  1. Abra dash.cloudflare.com → Realtime e entre na parte de TURN.
  2. Clique em Create (criar chave TURN) e dê o nome pairlan.
  3. Copie os dois valores que aparecem: o ID da chave TURN (vai em TURN_KEY_ID) e o API Token (vai em TURN_KEY_API_TOKEN).
Atenção: o API Token costuma aparecer uma vez só. Cole num lugar seguro até o passo 7. Ele nunca vai para o app: fica só no Worker, que gera credenciais TURN de 24 h para cada conexão.

Referência: Generate Credentials (Realtime TURN).

7Guardar os segredos no Worker

Cada comando pede o valor. Cole e tecle Enter:

npx wrangler secret put TURN_KEY_ID
npx wrangler secret put TURN_KEY_API_TOKEN
npx wrangler secret list

O secret list deve mostrar os dois nomes. Segredo novo vale na hora, sem novo deploy. Referência: Secrets.

Sem esses segredos o relay ainda funciona, mas só entrega STUN. Chat e anexos passam normal. Tela e voz podem não abrir em redes com NAT chato (4G, rede de empresa).

8Testar o relay

curl https://pairlan-relay.<seu-subdominio>.workers.dev/health
Esperado: {"ok":true}

Para ver erros ao vivo enquanto testa com o app:

npx wrangler tail

9Apontar o app para o relay

Opção A: nas Configurações (sem rebuild)

  1. Abra o PairLAN → Configurações → seção Internet.
  2. Cole a URL do passo 5 em Servidor (relay) e tecle Tab para salvar.
  3. Faça isso nos dois PCs.

Opção B: embutir a URL no build

Assim o AppImage já sai com o servidor padrão e ninguém precisa colar nada. Na raiz do repositório:

MAIN_VITE_RELAY_URL=https://pairlan-relay.<seu-subdominio>.workers.dev npm run dist

Para a release do GitHub: no repositório, abra Settings → Secrets and variables → Actions → Variables e crie a variável MAIN_VITE_RELAY_URL com a URL. O workflow de release já lê essa variável.

10Conectar os dois PCs

  1. Cada um registra um usuário em Seu usuário (3 a 20 letras minúsculas, números ou _) e clica em Registrar. No modo terminal: /usuario ana_dev.
  2. Cada um digita o usuário do outro em Usuário do par e clica em Adicionar. No modo terminal: /par bia_dev.
  3. Confira os códigos: o código do par no seu PC tem que ser igual ao seu código no PC do par. Leia em voz alta na call. Se for diferente, remova o par e não use.
  4. O topo do app mostra Conectado · via internet. O app guarda tudo e religa sozinho ao abrir.
Se os dois estiverem na mesma rede, o app prefere a LAN e pausa o relay sozinho.

11Cotas grátis

ServiçoGrátisUso do PairLAN
Workers100.000 requisições/diaRegistro, busca de usuário e abertura de conexão. Uma dupla usa poucas dezenas por dia.
Durable Objects100.000 requisições/dia, 13.000 GB-s/dia, SQLiteMensagens WebSocket contam 20:1. Com hibernação, sala parada não gasta duração.
Realtime TURN1.000 GB/mês (dividido com o SFU)Só quando o WebRTC direto falha. Tela a 8 Mbit/s ≈ 3,6 GB/hora.
STUNGrátis e sem limiteSempre usado para achar o caminho direto.

No plano Free, se passar de uma cota diária, aquele tipo de operação falha até 00:00 UTC. Não há cobrança surpresa nos Workers. No TURN, o que passar de 1.000 GB/mês custa US$ 0,05/GB. O painel pode pedir cartão para ativar o Realtime. Fontes: preços Workers, limites Durable Objects, preços Realtime.

12Problemas comuns

Mensagem no appO que fazer
Servidor fora do ar ou endereço errado.Teste o /health (passo 8). Confira se a URL começa com https:// e não tem barra ou caminho extra.
Esse nome já está em uso.Outra pessoa (ou outra instalação sua) já pegou o nome. Escolha outro.
Aguardando @par…O par precisa estar com o app aberto e ter adicionado você.
A chave do par não confere.O par reinstalou ou trocou de PC (chave nova). Remova o par, adicione de novo e confira o código.
Seu usuário não existe neste servidor.O app aponta para outro relay, ou o nome foi liberado. Registre de novo.
Seu usuário entrou em outro lugar.O mesmo usuário está aberto em outro PC. Feche um dos dois.
Muitas tentativas. Espere um minuto.Limite de taxa do relay (10 registros e 30 conexões por minuto por IP).
Chat ok, mas tela/voz não abreFaltam os segredos TURN (passos 6 e 7). Confira com npx wrangler secret list.

A chave de identidade de cada PC fica no arquivo identity.json, na pasta de dados do PairLAN em ~/.config/ (junto do config.json). Apagar esse arquivo gera uma chave nova: o usuário antigo fica preso à chave velha e você precisa registrar outro nome.

13Atualizar ou remover

Atualizar o relay depois de um git pull

cd pairlan/relay
npm install
npm run deploy

Remover tudo

npx wrangler delete

Depois apague a chave TURN em Realtime → TURN.
